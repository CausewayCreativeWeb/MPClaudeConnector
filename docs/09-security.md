# 09 — Security

## Threat model (short)

| Threat | Main controls |
| --- | --- |
| Stolen or leaked Application Password | Per-device passwords, individual revoke, HTTPS only, rate limits, audit log with device name and IP, Publisher passwords only on locked, encrypted devices |
| Prompt injection (instructions hidden in pasted emails, press releases, web pages: "publish this", "delete the latest post") | Contributors can't publish; every live change needs a prepare → human "yes" → token step; one post per action; daily caps; email to Publishers on every live change; Bin-only deletes |
| Claude misreading an instruction | Same as above, plus post verification and revisions before live updates |
| Over-broad access via MCP | Dedicated MCP server with an explicit ability list; default adapter server not exposed; no settings/users/pages/plugins abilities |
| Malicious uploads | Type checked by content, size limits, re-encoding, metadata stripped, PDFs checked by header, private temp dir |
| XSS via content or fields | `wp_kses` allow-list, no `unfiltered_html` for Bridge roles, typed field validation, late escaping in admin UI |
| CSRF in admin UI | REST nonce on every call; upload page POST protected by nonce + secret token |
| Personal data in Claude | Staff guidance and training; each person's own Claude Pro account with privacy settings checked at onboarding; EXIF/GPS stripped from photos |

## Requirements

### Access control
- Every ability: `permission_callback` checks capability; `execute_callback` checks again plus post type, status and ownership rules (`docs/02`).
- Every REST route: `permission_callback`; writes require `manage_options`.
- No ability or route for permanent deletion, users, roles (outside the admin UI), settings, plugins, themes, pages, menus or Elementor data.
- Bridge roles never get `unfiltered_html`, `manage_categories`, `edit_pages`, `edit_theme_options` or `manage_options`.

### Input and output
- JSON Schema validation for all ability inputs and the config.
- Sanitise early: `sanitize_text_field`, `sanitize_textarea_field`, `sanitize_key`, `sanitize_email`, `esc_url_raw`, `absint`, `wp_kses` for HTML.
- Escape late: `esc_html`, `esc_attr`, `esc_url`, `wp_json_encode` for script data (via `wp_add_inline_script`, never echoed inside `<script>`).
- All SQL via `$wpdb->prepare()`.
- CSV export: prefix cells beginning with `=`, `+`, `-`, `@`, tab or carriage return with `'`.
- Config import ≤ 256 KB, fully validated, diffed before applying.

### Secrets
- Confirmation tokens and upload-link tokens: 32 bytes from `random_bytes`, base64url; store SHA-256 hashes only; compare with `hash_equals`.
- Never log Application Passwords, `Authorization` headers, tokens or full post content. Debug mode logs request/response bodies with those fields redacted, and turns itself off after 24 hours.
- The setup pack contains no credentials.

### Transport and infrastructure
- HTTPS required for abilities and upload links.
- MCP endpoint: excluded from page caches and CDN caching; Cloudflare (or other WAF) rules must not challenge it; rate rule at the edge as a second layer.
- No external assets in admin pages; one outbound call (postcodes.io) with timeout and caching.

### Uploads
- Private temp dir under uploads with deny rules; files deleted after processing.
- Final filenames generated by the plugin, never from user input.
- Upload links: single use, ≤ 60 minutes, rate-limited, bound to user + post + purpose, `noindex`, no caching.

### Logging and monitoring
- Audit row for every ability call, admin change, role change and revoke.
- Health check daily and after updates; email on failure; alert on repeated errors.

### Recovery
- Full site backup confirmed before go-live.
- Deactivating the plugin removes the MCP server and cuts access instantly without affecting the site.
- Bin restore and revisions cover content mistakes.

## Security review checklist (before go-live)

- [ ] Every ability tested with: no auth, Contributor, Publisher, admin; wrong post type; wrong status
- [ ] Contributor can't publish or schedule via any ability, including by sending `status: publish` to create/update
- [ ] Live actions refused without token, with an expired token, a reused token, another user's token, and a token for a different post or payload
- [ ] Default MCP Adapter server and its discover/execute tools not reachable
- [ ] No `_elementor_*` meta ever written (integration test asserts this)
- [ ] Terms never created (integration test)
- [ ] Upload pipeline rejects: SVG, HEIC, PHP renamed to `.jpg`, polyglot JPEG/PHP, oversized files, PDFs without `%PDF-` header
- [ ] EXIF and GPS absent from processed images
- [ ] Upload link: reuse, expiry, wrong type, other user's post
- [ ] XSS attempts in title, content, excerpt, fields, alt text and config strings are neutralised
- [ ] CSV export formula injection neutralised
- [ ] PHPCS security sniffs clean; PHPStan clean
- [ ] Rate limits and daily caps enforced
- [ ] Logs contain no secrets
- [ ] WAF/CDN rules verified on the live domain

Findings are written up as a short report for the client: what was tested, issues found, fixes made, accepted risks.
